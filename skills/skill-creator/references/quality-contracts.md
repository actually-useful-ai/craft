# Quality and composition contracts

## Skill roles

- **Executor:** performs a bounded task and owns its method.
- **Overlay:** modifies quality, tone, or evaluation without replacing the executor.
- **Governor:** selects, sequences, or constrains other capabilities.
- **Auditor:** inspects and reports; it does not apply its own fixes.

State the role when confusion would cause routing or authorization errors.

## Trigger fixtures

Test at least:

- one phrase that must activate;
- one ordinary nearby phrase that must not activate;
- one explicit invocation;
- one composition case with a likely neighboring skill;
- one missing-capability case.

## Completion contract

For substantive work, define observable success evidence. Prefer tests, rendered behavior, resolved links, version/hash parity, or a reproducible lookup over self-rated quality.

Run at most one revision gate:

1. Is the actual objective satisfied?
2. Is one high-value omission still within scope?
3. Is any complexity present only to perform sophistication?
4. Can the result be simplified without losing value?
5. Is every consequential claim supported or explicitly uncertain?

Do not print the gate unless the user requests a critique.

## Anti-performance filter

Do not make a skill look powerful by requiring unnecessary headings, agents, tools, examples, dependencies, scores, visualizations, or files. Every requirement should change execution, reduce risk, or improve verification.
