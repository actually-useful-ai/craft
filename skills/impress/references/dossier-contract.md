# Dossier contract

Use one shared shape so domain guidance stays composable and easy to audit.

Each dossier should contain:

1. **Evaluator:** the informed audience whose judgment defines quality.
2. **Governing principle:** one memorable sentence.
3. **Audience modes:** meaningful differences between novice, practitioner, and expert surfaces.
4. **Exemplar signals:** qualities worth adding.
5. **Expert-noticed distinctions:** concepts that must not be collapsed.
6. **Anti-patterns:** impressive-looking moves that reduce quality.
7. **Evidence standard:** what must be sourced, measured, or verified.
8. **Acceptance checks:** observable conditions for completion.
9. **Boundaries and handoffs:** which other skill remains authoritative.

Keep dossiers concise. Include only domain knowledge that changes decisions. Do not repeat the base Exemplar process or anti-performance filter.

## Good dossier behavior

- Loads only for a relevant task.
- Changes concrete implementation or evaluation decisions.
- Names distinctions that a general-purpose model may flatten.
- Uses acceptance conditions instead of self-ratings.

## Bad dossier behavior

- Repeats generic advice such as “be clear” or “consider edge cases.”
- Requires every task to use every criterion.
- Adds a domain persona without domain evidence practices.
- Expands the user’s requested deliverable by default.
