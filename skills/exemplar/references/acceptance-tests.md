# Routing and composition acceptance tests

Use these fixtures when Exemplar's description, workflow, or neighboring
governors change. Record the runtime and resolved skill path for an actual
activation test.

## Positive triggers

- “Impress me with this launch page.”
- “Make this research brief exceptional.”
- “Treat this as the flagship implementation.”
- “Use Exemplar on the etymology explorer.”

Expected: Exemplar activates as an overlay. The most specific domain skill keeps
method ownership, and one relevant dossier loads.

## Negative triggers

- “Polish this sentence.”
- “Apply the standard production-readiness checklist.”
- “Fix the typo in this heading.”
- “Improve this query's execution time.”

Expected: Exemplar does not activate unless the request also asks for an
exceptional or exemplar-quality pass. Route to the specific writing, release,
editing, or software skill.

## Composition cases

- “Chef's choice: impress me with the onboarding flow.” Chef's Choice selects
  useful capabilities; Exemplar sets the quality bar; product design owns the
  method; accessibility keeps compliance authority.
- “Make this paper exceptional and humanize the abstract.” Research owns
  evidence; Exemplar selects expert criteria; Humanize owns meaning-preserving
  prose edits.
- “Audit Exemplar.” Skill Auditor remains read-only. Exemplar does not authorize
  edits or add ornamental criteria to the report.
- “Use Intentional UX and Exemplar on this onboarding flow.” Intentional UX owns
  the task path, evidence levels, recovery states, and experience acceptance
  checks; Exemplar sets the quality target and anti-performance filter; the
  product-design skill owns implementation.

## Missing-capability case

When a named dossier, domain skill, or optional tool is unavailable, use the
base Exemplar process with the closest supported evidence standard. Do not
invent a capability, fail the task solely because a brand-name tool is absent,
or expand authorization.

## Completion evidence

For each supported runtime and host, record:

- the resolved Exemplar path and source version or content hash;
- which positive and negative fixture routed;
- which domain skill and dossier, if any, composed with it;
- the observable task result and its verification;
- any intentional runtime-specific difference.

Semantic fixture predictions remain **Assumed** until a runtime invocation
confirms them. Paths, versions, hashes, and captured results can be **Measured**.

## Critique mode

Fixture: provide an adequate artifact containing one dossier-relevant omission
and one decorative complication, then request “Exemplar critique.”

Expected:

- output contains `Merely competent`, `Exemplar opportunities`, and
  `Performative sophistication` in that order;
- no section contains generic praise or an artifact summary;
- opportunities are limited to one or two changes and each has an observable
  acceptance condition;
- the decorative complication is recommended for removal or simplification;
- no revision occurs without separate authorization;
- correctness, invalid framing, or dependency impact is handed to the matching
  Reconsider mode rather than being silently absorbed.
